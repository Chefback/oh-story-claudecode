# 产线方法论：AI 网文创作的核心思路

> 本文件是写作 skill 的理论锚点，定义"为什么这样写"。技法细节分散在 25+ 个参考文件中，本文件串联它们。

---

## 核心洞察：套路 = 确定性的情绪满足

商业网文的"套路"不是陈词滥调，而是经过大量读者验证的情绪交付机制。每一类套路对应一类确定的情绪需求：

| 套路类型 | 交付的情绪 | 读者心理 |
|----------|-----------|---------|
| 打脸逆袭 | 爽感释放 | 被压抑时的代偿满足 |
| 身份反转 | 震撼+痛快 | 信息不对称的优越感 |
| 感情拉扯 | 意难平 | 得不到的放大效应 |
| 装逼日常 | 期待感 | "他还会怎么秀"的悬念 |

**写每一个场景前，先问：这个场景交付什么情绪？如果答不出，这个场景不该写。**

## 产线五支柱

### 1. 爆款逆向

从市场验证的爆款出发，逆向拆解→复用→改编，而非从灵感正向构建。

专业作者的方法论：扫榜(Scan) → 拆文(Deconstruct) → 商业化写作(Commercialize)。

在我们的 skill 体系中：
- 扫榜由 story-long-scan / story-short-scan 执行
- 拆文由 story-long-analyze / story-short-analyze 执行
- 写作由 story-long-write / story-short-write 执行

**关键原则**：先有对标，再有创作。不是"我想写什么"，而是"市场验证了什么有效，我如何用我的方式重新交付"。

参考技法：genre-readers.md（读者心理）、genre-catalog.md（题材框架）

### 2. 剧情模块化

将剧情分解为可检索、可替换、可组合的单元（Slot），每个模块有：
- 触发条件（什么场景需要这个模块）
- 情绪目标（这个模块交付什么情绪）
- 输入输出（需要什么角色状态，产出什么状态变化）

来自不同书的剧情模块需要做**角色位抽象**：把"前女友"抽象为"关系破裂的对手"，把"演唱会"抽象为"公共场合的才艺展示"。这样模块才能跨书复用。

长篇参考：narrative-units.md（叙事单元体系）、plot-frameworks.md（剧情框架）
短篇参考：villain-and-reveal.md（反派与揭露设计）
通用参考：reversal-toolkit.md（反转工具）、emotional-arc-design.md（情绪弧线）

### 3. 状态分层

PPT 的核心架构：粗格栅(大纲) → 细格栅(细纲) → 正文，三层递进，上层指导下层。

每一层有独立的**状态追踪**：

| 层级 | 产出 | 状态追踪 | 追踪文件 |
|------|------|---------|---------|
| 粗格栅 | 卷纲、剧情线 | 跨卷伏笔、全书时间线 | 追踪/伏笔.md、追踪/时间线.md |
| 细格栅 | 每章细纲 | 角色当前状态、待回收伏笔 | 追踪/角色状态.md |
| 正文 | 每章正文 | 日更进度摘要 | 追踪/上下文.md |

**关键原则**：写作时只加载"最简记忆包"——只保留"如果不知道这个，本章会写错"的信息。不做全量加载，避免上下文稀释。

长篇参考：outline-methods.md（大纲方法）、outline-rhythm.md（节奏）
短篇参考：writing-workflow.md（短篇工作流）
通用参考：writing-craft.md（写作技法）、emotional-methods.md（情绪技法）

### 4. 人机协同

人领 AI 随：人给方向和决策，AI 规模化执行。

在我们的 skill 体系中，每个 Phase 都有**人工确认点**：
- Phase 1：选题方向确认
- Phase 2：核心设定确认
- Phase 3：大纲锁定（未经用户确认不得修改）
- Phase 4：每章写前准备层确认（准备层 3 步的输出）
- Phase 5：质检结果确认

**关键原则**：AI 不做最终决策。AI 提供建议和选项，人做选择。

### 5. 拆文→写作的数据闭环

story-long-analyze 的产出不只是"拆文报告.md"一个文件，而是一个结构化的目录：

```
拆文库/{书名}/
├── 角色/{角色名}.md        ← 结构化角色卡
├── 剧情/{剧情线名}.md      ← 结构化剧情线
│   └── 故事线.md           ← 剧情线索引
├── 设定/世界观.md、金手指.md ← 结构化设定
├── 章节/第{N}章_摘要.md    ← 线性概述
└── 拆文报告.md             ← 综合报告
```

写作 skill 在准备层的"模块召回"步骤中，应该从这些结构化产出中检索与当前章节最相关的角色、剧情、设定，而不只是读一个汇总报告。

**数据流**：analyze 产出 → 对标/（或拆文库/回退）→ 写作 skill 消费 → 准备层模块召回。

## 跨项目资源（设计方向）

PPT 的产线架构有一个跨项目的"资源库"：大纲模板、设定库、剧情库、卖点元素库、语料库。

在当前 Claude Code skill 环境中的映射：
- 拆文库/ 是事实上的资源库 — 每个 analyze 产出的结构化目录都可以被后续写作项目复用
- references/ 是技法库 — 25+ 参考文件提供跨项目的写作技法
- 对标/ 下的结构化子目录是项目级资源入口 — 从拆文库同步到具体项目

未来产品化方向：
- 统一的素材检索服务（替代当前"读目录+手动匹配"的方式）
- 跨项目的剧情模块标签索引（题材、情绪、角色关系）
- 基于向量检索的模块召回（替代当前 LLM 自由回忆）
